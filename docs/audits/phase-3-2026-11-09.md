# Fase 3 — Audit dan Kurasi Kurikulum Smart Energy Monitoring

**Tanggal:** 9 November 2026  
**Basis audit:** `main` commit `401299b`; perbaikan dikirim dalam commit fase 3.  
**Cakupan:** 16 modul, contoh, teori, praktik, evidence, security, workflow CI, dan kontrak domain.

## Executive summary

Audit menemukan **akar masalah lintas-modul** setelah migrasi use case dari klasifikasi teks ke pemantauan energi: schema CSV berbeda antar dokumen, nama route API tidak valid, unit energi dan status model tertukar, identitas event tidak konsisten, dan tugas training numerik masih merujuk classifier teks. Pemeriksaan CI terdahulu hanya memastikan link/fence/larangan kata tertentu, **bukan ketepatan domain**.

## Temuan, risiko, dan perbaikan

| Severity | Temuan | Dampak jika ditiru peserta | Mitigasi dalam fase 3 |
| --- | --- | --- | --- |
| High | CSV `timestamp` vs `interval_start_utc`; durasi interval tidak eksplisit | Data tidak sebanding, salah unit kWh/kW | Canonical 8-field schema UTC 15 menit dan sinkronisasi SRS/datasets/casebook |
| High | `UNIQUE(tenant_id,source_event_id)` vs site/meter identity | Duplikasi atau konflik lintas meter; data overwrite | `UNIQUE(site_id,meter_id,source_event_id)`; konflik payload tidak di-overwrite |
| High | Model numeric bercampur text classification dan `normal/warning/fault` | API contract tidak valid; metrik dan latihan model salah sasaran | Pisahkan Week 01 text classifier dari Week 11–12 numerical anomaly scoring |
| High | Route `POST /meter readings` memuat spasi | Endpoint contoh tidak valid | Rute canonical `POST /api/v1/import-batches` dan site-scoped read/review routes |
| High | Missing interval disamakan dengan kWh nol pada contoh | Aggregation/visualisasi dan detection menyesatkan | Coverage-aware quality, gap ≠ zero; negative examples |
| High | Izin site/object belum konsisten di DB/API/UI | IDOR/BOLA atau cross-site data leak bila diterapkan | Server-side site membership; threat model, query scoping, negative test plan |
| Medium | Accuracy teks Week 01 tersirat sebagai acuan angka model numerik | Evaluasi dan klaim AI yang keliru | Metrics Week 01 dipisah, Week 11 menggunakan synthetic injected labels + chronological splits |
| Medium | Deep dive/praktikum sering masih berisi istilah konteks sebelumnya | Learning transfer buruk | Revisi teori Week 03–12, worked examples, deep dives dan lab guides; workbook domain 16 modul |
| Medium | CI tidak memeriksa schema satuan/API | Regresi domain tetap lolos | `check_energy_integrity.py`, 9 unit tests dokumen, workflow docs-quality diperluas |
| Medium | Bukti BNSP terkesan otomatis dari tersedianya materi | Klaim kompetensi tidak berdasar | Status planned vs tested vs LSP-assessed dibedakan; tetap minta dokumen KUK LSP terkini |

## Kode dan quality assurance

**Yang harus diperiksa sesudah push:**
1. `python scripts/check_curriculum.py` (tautan lokal, fenced code, 16×9 documents).
2. `python scripts/check_use_case.py` (istilah domain lama yang dilarang).
3. `python scripts/check_energy_integrity.py` (kontrak data, negative keywords, numerical example).
4. `python -m unittest discover -s tests -v` (doc/example logic; separate from Week 01 suite).
5. GitHub Actions Week 01: `python -m unittest discover -s tests -v` dalam folder latihan.
6. Bandingkan status CI dengan commit yang benar, bukan sekadar screenshot hijau dari commit sebelumnya.

**Catatan:** audit dokumentasi dan static checks tidak membuktikan seluruh penjelasan benar secara empiris. Contoh integrasi, keamanan aplikasi dan deployment masih merupakan *plans*. Kesesuaian dengan elemen/KUK LSP belum dapat diverifikasi tanpa dokumen skema final.

## Risiko yang tersisa

- **Kesiapan BNSP:** unit/kode yang terpublikasi dapat berbeda dengan skema terbaru. Kepmenaker 103/2026 telah menggantikan 123/2021; minta skema/KUK LSP resmi.
- **Aplikasi:** backend/frontend numerik, dataset generator dan full-stack tests Week 02–16 **belum dibuat**; jangan mengklaim performance/security/deployment success.
- **Pengajaran:** semua 16 modul sudah punya materi dan applied case, tetapi pembelajaran personal, latihan, dan review asesor belum dilakukan.
- **Keamanan:** threat model adalah design-time; auth, IDOR controls, rate limiting, CI supply chain scan dan backups baru bisa diuji pada implementasi sesungguhnya.
- **Energy domain:** synthetic telemetry tidak menjadi jaminan keselamatan listrik atau akurasi sensor.
