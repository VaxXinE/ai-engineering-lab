# Simulasi Asesmen — Week 05

**Ini latihan pribadi, bukan soal, asesmen, atau panduan resmi BNSP.**

## Tanya jawab teknis

1. Apa beda dict, set, list dan deque?

2. Apa arti O(n) dan O(n²)?

3. Kapan list tetap lebih baik daripada set?

4. Bagaimana deterministic output membantu testing?

5. Bagaimana menangani duplicate ID secara konsisten?

6. Apa risiko input tidak dibatasi?

7. Mengapa benchmark harus mencatat lingkungan?

8. Apa trade-off memori ketika memakai lookup table?

## Demo praktis yang perlu disiapkan

- [ ] Tunjukkan bukti: Implementasi menyimpan satu item per unique ID dan punya aturan 'first wins' atau 'last wins' jelas.
- [ ] Tunjukkan bukti: Semua input edge case diuji.
- [ ] Tunjukkan bukti: Analisis Big O dan memory trade-off ditulis.
- [ ] Tunjukkan bukti: Benchmark menyertakan lingkungan, jumlah record, dan metode.

## Penilaian diri

- **Belum bisa:** belum dapat menjelaskan atau mendemonstrasikan.
- **Perlu latihan:** bisa dengan bantuan tetapi belum konsisten.
- **Mandiri:** bisa menjelaskan dan mendemonstrasikan sendiri, beserta error path.
- **Siap dievaluasi:** bukti direproduksi dan risiko tersisa dijelaskan.

Jangan menganggap skor ini menentukan status **Kompeten** BNSP. Keputusan resmi memerlukan prosedur dan asesor LSP.
